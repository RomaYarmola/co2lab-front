# SEO-аудит co2lab.com

Дата: 2 серпня 2026 · Стек: Next.js 16 (App Router), Tailwind 4, Sanity CMS

---

## 1. Що зроблено

### 1.1 Мультимовність (EN / UK / RU)

| Що | Як реалізовано |
| --- | --- |
| Маршрутизація | `src/app/[locale]/…`; EN у корені (`/about`), UK і RU з префіксом (`/uk/about`, `/ru/about`) |
| Middleware | `src/middleware.ts` — `/en/*` віддає 308 на канонічний URL без префікса, решта переписується на `[locale]` без зміни адреси в браузері |
| Словники | `src/i18n/messages/{en,uk,ru}.ts`, типізовані від EN — пропущений ключ ловиться на етапі `tsc` |
| Перекладач | серверний `getTranslator(locale, ns)`, клієнтський `useTranslations(ns)` через `I18nProvider` |
| `html lang` | виставляється з локалі маршруту |
| Перемикач мов | `LanguageSwitcher` — у списку тільки **EN + UA**. **RU прихована**: доступна за прямим URL, присутня в `hreflang` і sitemap, тобто індексується |

**Чому автоматичного редіректу за `Accept-Language` немає.** Такий редірект заважає
краулеру Google (він ходить із США і бачив би тільки EN) і ламає прямі
посилання на UK/RU. Мова обирається користувачем або приходить із видачі.

### 1.2 Метатеги

- `createPageMetadata()` (`src/utils/createMetadata.ts`) віддає для кожної сторінки:
  `title`, `description`, `keywords`, `canonical`, `hreflang` (usiх 3 мов + `x-default`),
  Open Graph (з `og:locale` та `alternateLocale`), Twitter Card, директиви robots
  з `max-image-preview:large` і `max-snippet:-1`.
- Заголовки/описи всіх сторінок лежать у словнику під `seo.*` — переклад в одному місці.
- Динамічні сторінки (товар, категорія, стаття) беруть meta з Sanity з фолбеком
  на назву та короткий опис — сторінка ніколи не лишається без description.
- `title.template` = `%s | CO₂ Lab`.

### 1.3 Локалізовані URL (важливо для позицій)

Товари, категорії та статті мають **окремий slug на кожну мову**
(`localizedSlug` у Sanity):

```
/catalog/cryogenic-co2-tank
/uk/catalog/kriogennyi-rezervuar-co2
/ru/catalog/kriogennyi-rezervuar-co2
```

`buildAlternatesFromSlugs()` збирає `hreflang` з усіх slug-ів одного документа,
тому Google коректно склеює переклади. Локалі без заповненого slug у
`hreflang` не потрапляють — краще не вказати альтернативу, ніж вказати чужу.

### 1.4 Мікророзмітка (JSON-LD)

| Схема | Де |
| --- | --- |
| `Organization` + `WebSite` (+ `SearchAction`) | у layout, на кожній сторінці, з `@id` для перехресних посилань |
| `BreadcrumbList` | каталог, категорії, товар, блог, стаття |
| `Product` + `Offer` | сторінка товару; для «ціна за запитом» — `PriceSpecification` без значення (валідно для Google) |
| `ItemList` | каталог і сторінка категорії |
| `Blog` + `BlogPosting` | список статей |
| `BlogPosting` | сторінка статті: автор, дати, `articleSection`, `timeRequired` |
| `FAQPage` | товар, категорія, стаття — там, де заповнений FAQ |

### 1.5 Sitemap і robots

- `/sitemap.xml` — індекс із трьох файлів.
- `/sitemap-static.xml`, `/sitemap-catalog.xml`, `/sitemap-blog.xml`.
- Кожен `<url>` містить `xhtml:link rel="alternate"` для всіх мов + `x-default` —
  це рекомендований Google спосіб декларувати переклади.
- `lastmod` береться з `_updatedAt` документа Sanity.
- `robots.txt`: відкрито все крім `/api/` і параметра `?q=` (клієнтський пошук
  каталогу — нескінченні комбінації, індексувати їх немає сенсу).

### 1.6 Каталог і товари

- `/catalog` — усі товари, категорії-пігулки (звичайні `<a>`, краулер їх бачить),
  клієнтський пошук і сортування без зміни URL.
- `/catalog/category/[slug]` — окрема індексована сторінка з власним H1,
  SEO-текстом (Portable Text) і FAQ.
- `/catalog/[slug]` — картка товару: галерея з лайтбоксом, характеристики
  (згруповані), особливості, застосування, PDF-документи, FAQ, схожі товари.
- Галерея й листалка фото в картках перенесені з `your-house-albania`
  (сітка 1–5 прев'ю, лайтбокс зі стрічкою мініатюр, свайп на мобільних)
  і перекладені в монохромний дизайн CO₂Lab.

### 1.7 Блог

- `/blog` — перший пост великою карткою, решта сіткою, фільтр за категоріями.
- `/blog/category/[slug]` — окрема індексована сторінка.
- `/blog/[slug]` — стаття: обкладинка, автор (E-E-A-T), дати публікації й
  оновлення, зміст із якорями (`id` на H2/H3 — Google може показати jump-links),
  Portable Text із таблицями/CTA/зображеннями, FAQ, повʼязані товари й статті.
- Час читання рахується автоматично, якщо не заданий у CMS.

### 1.8 Технічна база

- Усі сторінки — SSG (`generateStaticParams` × 3 локалі) з ISR 5 хв.
- Вебхук `/api/revalidate/sanity` скидає кеш за тегом типу документа.
- `next/image` + Sanity CDN (`auto=format`, avif/webp), `remotePatterns` налаштовано.
- Alt-текст зображень — обовʼязкове локалізоване поле в CMS.
- FAQ на `<details>/<summary>` — відповіді є в HTML навіть у згорнутому стані.
- Заголовкові теги: рівно один `H1` на сторінку, далі `H2`/`H3` без пропусків.
- Security-заголовки (HSTS, X-Content-Type-Options, Referrer-Policy) — впливають
  на оцінку «Best practices» у Lighthouse.
- `trailingSlash: false` + канонікали без слеша — жодних дублів `/page` vs `/page/`.

### 1.9 Sanity-адмінка (`../co2lab-admin`)

Типи: `product`, `productCategory`, `blogPost`, `blogCategory`, `author`,
`siteSettings`. Field-level локалізація (`{en, uk, ru}` в кожному текстовому полі)
— один документ на сутність, звʼязки й медіа не дублюються.
На кожному документі є група SEO: `metaTitle`, `metaDescription`, `keywords`,
`ogImage`, `noIndex`, `canonicalUrl` — усі локалізовані, з мʼякою валідацією
довжини (30–60 / 120–160 символів).

## 2. Що треба зробити далі

### 2.1 Блокери запуску (зробити першим)

1. **Створити проєкт Sanity і заповнити `.env`.**
   Поки `NEXT_PUBLIC_SANITY_PROJECT_ID` порожній, каталог і блог показують
   **демо-контент** із `src/lib/sanity/demoData.ts` (3 товари, 3 статті,
   3 категорії продукції, 2 категорії блогу — усі трьома мовами).
   Це дозволяє тестувати верстку до підключення CMS; щойно зʼявиться
   `projectId`, фікстури автоматично перестають віддаватись.
   ```bash
   cd ../co2lab-admin && npm install && npx sanity init
   ```
   Після наповнення реальним контентом демо-файл можна видалити разом
   із гілками `if (!isSanityConfigured)` у `src/lib/sanity/fetchers.ts`.
2. **`NEXT_PUBLIC_SITE_URL`** — від нього залежать canonical, hreflang, sitemap
   і JSON-LD. Зараз фолбек `https://co2lab.com`.
3. **Налаштувати вебхук** Sanity → `/api/revalidate/sanity?secret=…`.
4. **Наповнити контентом**: мінімум 8–12 товарів по 3–5 фото, 4–6 категорій із
   SEO-текстом на 300+ слів, 5–8 статей.

### 2.2 Переклад контенту — **зроблено**

Перекладено на три мови повністю: навігація, футер, форми, повідомлення,
CTA, каталог, товари, блог, усі meta-теги **і тіла всіх маркетингових
сторінок** — головна, «Про нас», «Постачання», три сторінки рішень,
контакти, а також юридичні тексти (Політика конфіденційності, Умови
використання).

Копії лежать у `src/i18n/messages/pages/{en,uk,ru}.ts`. Тип `PagesMessages`
виводиться з англійської версії, тож пропущений ключ у UK/RU ловиться
`tsc`, а не в проді.

Юридичні сторінки рендеряться спільним компонентом
`src/components/legal/LegalPage.tsx` зі структури у словнику — щоб
оновити текст, верстку чіпати не треба.

**Що лишилось із контенту:** вичитка носієм мови. Переклад технічно
коректний, але для комерційних сторінок варто, щоб його переглянув
галузевий фахівець — особливо терміни (`уловлювання` vs `вловлювання`,
`зрідження` vs `скраплення`).

### 2.2.1 Адаптив — перевірено й полагоджено

Пройдено 375 / 768 / 1024 / 1280 / 1440 px на всіх сторінках. Горизонтального
скролу сторінки немає ніде (виносні блоки лежать під `overflow-hidden`).

Виправлено під час перевірки:

| Проблема | Рішення |
| --- | --- |
| На планшеті меню з 7 пунктів + перемикач мов не вміщувалось | Повне меню від `xl` (1280), нижче — бургер |
| На 1024 пункт «Про нас» переносився у два рядки | `whitespace-nowrap` на пунктах + поріг `xl` |
| Бургер із чорними лініями на темному hero (1024–1279) | Прапорець `lightOnLg` — лінії білі там само, де білий логотип |
| Кириличний текст вилазив за межі овальних карток «переваг» | Прибрано жорсткі піксельні `max-w` на мобільному, додано `px-5` і більшу висоту |
| Картки переваг ставали по одній у рядок (1px переповнення) | `flex-basis: calc(50%-8px)` → CSS Grid |
| У таблиці порівняння слова рвались посеред складу | `min-w-[520px]` + горизонтальний скрол таблиці на мобільному |
| `w-dvw` на бекдропі давав зайвий горизонтальний скрол | Прибрано, лишився `inset-0` |

**Лишилось:** посилання у футері мають висоту 18 px при відступах 16 px —
менше за рекомендовані Google 48 px для тап-таргетів. Це успадкований
дизайн, змінювати без узгодження не став.

### 2.3 Аналітика та інструменти

- Google Search Console — окремо кожна мовна версія, подати `/sitemap.xml`.
- Bing Webmaster Tools (є імпорт із GSC).
- GA4 + Google Tag Manager, події на відправку форм і кліки «Запросити ціну».
- `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` уже підтримується в layout.

### 2.4 Контент і семантика (те, що реально рухає в топ-1)

Технічна база вже на рівні топ-1. Далі позиції визначає контент:

1. **Семантичне ядро** під три мови окремо. Не перекладайте ключі дослівно:
   англійське «CO2 capture unit», українське «установка вловлювання CO2» і
   російське «установка улавливания CO2» мають різну частотність і конкуренцію.
2. **Кластери сторінок**: під кожен комерційний запит — сторінка категорії
   з текстом 800–1500 слів, під інформаційні — статті блогу, що лінкуються
   на цю категорію.
3. **Внутрішня перелінковка**: статті → товари (поле `relatedProducts` уже є),
   товари → категорії, категорії → статті. Це головний недооцінений важіль.
4. **FAQ на кожній комерційній сторінці** — розмітка вже виводиться,
   лишилось заповнити в CMS.
5. **Унікальні описи товарів.** Скопійований текст від виробника не ранжується.
6. **Сторінки під галузі** (`/solutions/industries-we-serve` розбити на
   окремі сторінки: біогаз, харчова, хімія, переробка) — кожна під свій кластер.

### 2.5 Зовнішні сигнали

- Профілі в галузевих каталогах (Europages, Kompass, ThomasNet).
- Кейси та пресрелізи на профільних майданчиках із посиланням.
- Google Business Profile (Київ) — дає локальну видачу і карти.
- Партнерські посилання від IceLab і клієнтів.
- LinkedIn-сторінка компанії — вже вказана в `sameAs` розмітки Organization.

### 2.6 Продуктивність (Core Web Vitals)

Наступні кроки після наповнення контентом:

- Заміряти LCP на сторінці товару з реальними фото Sanity; за потреби
  додати `placeholder="blur"` із `lqip` (хелпер `getBlurDataUrl` уже є).
- Перевірити CLS на сторінках із галереєю.
- Розглянути `next/font` subset — зараз підключено `latin` + `cyrillic`,
  це коректно для трьох мов, але додає вагу.
- Декоративні SVG у героях віддавати через `priority={false}`.

### 2.7 Дрібне

- `alt="Smoke"` / `alt="Hero"` у старих секціях — замінити на описові або
  прибрати (декоративні картинки мають бути `alt=""` + `aria-hidden`).
- Додати `manifest.webmanifest` і `theme-color`.
- Сторінка 404 показує тексти дефолтною локаллю (обмеження `notFound()`
  всередині `[locale]`) — за потреби винести окремі `not-found` на маршрут.
- Розглянути `/uk/catalog/…` → RSS для блогу (дає індексацію свіжих статей швидше).

## 3. Швидка перевірка після деплою

```bash
curl -s https://co2lab.com/sitemap.xml
curl -s https://co2lab.com/uk | grep -i "hreflang\|canonical\|<html lang"
curl -s -o /dev/null -w "%{http_code}\n" https://co2lab.com/en/about   # має бути 308
```

Далі: Rich Results Test (`search.google.com/test/rich-results`) на сторінці
товару та статті, PageSpeed Insights на головній і сторінці товару.
